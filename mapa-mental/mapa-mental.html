Mapa mental: resolver un conflicto

Cinco ramas, una idea: Git pausa la operación y tú decides. El mapa está dibujado con Canvas HTML5 real, sin imágenes externas, y se puede exportar en alta resolución.

Canvas 1800 × 1250 px · exportación a 2× (3600 × 2500 px) · se adapta al ancho de la pantalla.

1 Detectar

Git avisa que no pudo unir dos cambios. Los archivos aparecen como UU y el archivo contiene marcas <<<<<<<.

Primero: git status --short

2 Entender

No se trata de borrar marcas, sino de saber qué quería cada lado. Compara tu versión, la del otro y la base común.

Clave: git diff y git show :1: :2: :3:

3 Resolver

Elige una versión, combina las dos o elimina el archivo. Después borra todos los marcadores y guarda el resultado.

Regla: una decisión por cada bloque.

4 Verificar

Comprueba que no quedan marcas, que las pruebas pasan y que el árbol queda limpio antes de confirmar.

Clave: git diff --check

5 Prevenir

Los conflictos se reducen con ramas cortas, integraciones frecuentes y avisos cuando dos personas tocan lo mismo.

Hábito: integrar seguido.

✓ Resultado

Un conflicto no es un error: es una pausa para tomar una decisión. Al terminarlo, el historial sigue y el trabajo de ambos lados se conserva.

El método en 4 pasos

Las cuatro primeras ramas son el ciclo de resolución. La quinta es lo que evita repetirlo:

1. Detecta el estado y los archivos afectados. 2. Entiende las dos versiones. 3. Resuelve bloque por bloque. 4. Verifica y confirma.

Por qué está hecho en canvas

  • Un solo archivo: el mapa se dibuja con JavaScript y no depende de imágenes ni servicios externos.
  • Editable: los textos y colores están en un arreglo de datos al inicio del script.
  • Exportable: el botón genera un PNG de 3600 × 2500 px listo para el documento o una diapositiva.
  • Accesible: el canvas incluye una descripción y la explicación de las cinco ramas está en HTML.
